# 开发路线图

> 范围基准：MVP 的 Must / Should / Won't 分层见 [`../产品策划文档.md`](../产品策划文档.md) 第 5.4 节。
> 排期口径：**3 人团队 × 8 周 + 1 周缓冲**。若团队 < 3 人（或缺少技术美术角色），切换 12 周口径。

## 关键路径

```
Provider 打通 → 生成落盘 → 修复/减面 → UV/烘焙 → 校验 → 导出 → 引擎实机验证
```

## 并行轨道

| 轨道 | 内容 | 备注 |
|---|---|---|
| T1 前端 | Electron 壳、3D 检查视口、资产库、设置页 | 依赖数据模型冻结（W1） |
| T2 后端 | FastAPI sidecar、任务队列、bpy/pymeshlab 管线 | 关键路径主体 |
| T3 规范 | 校验规则阈值、引擎导出预设、命名规范 | **W0 就要拿到真实阈值**，可用样例资产离线开发 |
| T4 产品/测试 | 黄金概念图集、验收用例、种子用户招募、埋点核对 | 全程并行 |

## 节点分解

| 节点 | 周次 | 目标 | 交付物 | 出口标准 |
|---|---|---|---|---|
| **M0** 立项与验证启动 | W0（3–5 天） | 冻结范围与技术选型 | 范围冻结表评审通过；黄金概念图集 10 张冻结；Provider 盲测方案发出；Spike 脚本可跑 | 范围表签字；盲测已发出；Spike 环境就绪 |
| **M1** 骨架贯通 | W1–W2 | 壳 + sidecar + 视口 + Provider 抽象 | 可启动的 Electron 应用；sidecar 生命周期管理；GLB 视口；Meshy/Tripo 各跑通一次；四边面重拓扑 Spike 结论 | UI 内选图 → 云生成 → 落盘 GLB → 视口打开端到端跑通；**W2 末拍板四边面去留** |
| **M2** 主链贯通 | W3–W4 | 修复/减面/UV 进管线 | 管线 v1；任务队列与进度回传；中间产物落盘；资产状态机落地 | 概念图 → 生成 → 减面至预算内 → UV 零重叠 → GLB 导出，UI 内全流程完成；黄金集 10 张全部跑通 |
| **M3** 质量闭环 | W5–W6 | 烘焙 + 校验 + 报告 + 导出预设 + 转台 | 烘焙脚本；校验规则引擎（7 条）；校验报告 UI（点击定位高亮）；转台渲染；Unity/UE 导出预设；3D 检查视口 v1 | 黄金集通过率 ≥ 50%（首轮基线）；导出文件在 Unity/UE 实机导入成功；报告可定位到面/UV 岛 |
| **M4** 产品化闭环 | W7 | 资产库 / 版本树 / BYOK / 成本 | 资产库与缩略图；版本树与回滚；BYOK 设置与连通性自检；成本预估与预算上限；工作流 C 入口 | 关闭应用重开，资产与版本树完整；BYOK 错 Key/断网有明确提示；超预算被拦截 |
| **M5** 打磨与封测 | W8 | 稳定性与可用性 | 崩溃与错误处理；首次使用引导；安装包与更新通道；内部封测报告 | Release Gate 全过；内部连续 20 次任务无崩溃 |
| **M6** 种子用户 alpha | W9（缓冲 + 外测） | 外部验证 | 3–5 名美术实测；问题清单；TTFE 与变体采纳率数据；alpha 复盘报告 | ≥3 人独立完成"概念图 → 引擎"；复盘报告给出 Phase 2 排序建议 |

## 三个前置决策点

| 决策点 | 时间 | 不决策的后果 |
|---|---|---|
| 四边面重拓扑是否进 MVP | **W2 末**（依据 M1 的 Spike 结果） | 拖垮关键路径；后期返工管线 |
| 校验阈值与引擎规范从哪来 | **W0**（访谈 2–3 位目标工作室美术，或用公开规范） | M3 校验器与导出预设全部返工 |
| 云生成质量是否达"道具级可用" | **W2 末**（依据 M1 盲测） | 若为否，启用 B 计划：MVP 重心前移到工作流 C |

**黄金集纪律**：W0 冻结的 10 张概念图全程不得更换，作为每一节点的回归基线。

## 发布门槛（Release Gate）

| # | 门槛 | 判定 |
|---|---|---|
| G1 | 黄金集 10 张，TTFE P50 ≤ 10 分钟（含人工挑选） | 实测 |
| G2 | 校验器一次通过率 ≥ 70%（含一轮自动重试） | 实测 |
| G3 | 导出资产在 Unity 2022 LTS 与 UE5 实机导入无报错，贴图通道正确 | 实机 |
| G4 | 连续 20 次任务无崩溃，无 P0/P1 级 bug | 压力跑 |
| G5 | 成本预估与实际偏差 ≤ 20% | 对账 |
| G6 | 3–5 名外部美术不看文档独立跑通，成功率 ≥ 80% | 外测 |
| G7 | 源概念图未被修改；所有产物在独立输出目录且带版本号 | 文件检查 |

## 人力配置

| 角色 | 投入 | 职责 |
|---|---|---|
| 前端 / 桌面 | 1 人 | Electron + React + react-three-fiber |
| 后端 / 管线 | 1 人 | FastAPI sidecar、任务队列、bpy 管线 |
| 技术美术（TA） | 0.5 人 | 校验规则、导出预设、引擎实机验证 —— **关键角色** |
| 产品 / 测试 | 0.5 人 | 黄金集、验收用例、种子用户、埋点 |

## 埋点（MVP 必做）

任务耗时、每步耗时、失败原因分类、生成次数与花费、变体是否被选中、校验明细、导出次数与引擎类型。
本地 JSONL，默认不上传；alpha 期由用户手动导出上报。

## 已知缺口（首版代码留下的，按节点认领）

| # | 缺口 | 影响 | 认领节点 |
|---|---|---|---|
| 1 | **UV 展开无法保证零重叠**：xatlas 的 Python 绑定不暴露 padding 参数，实测约 0.04% 的面有微小重叠 | 校验器的 UV 重叠规则暂时按 WARN 报，不阻断导出 | M3：换 Blender Smart UV Project 或补去重叠后处理，然后把规则改回 FAIL |
| 2 | **四边面重拓扑未实现**：`want_quads` 只被记录，实际输出仍是三角面 | 四边面规则在配置里默认关闭 | W2 末的 Spike 结论决定是否真做（见 5.4.3） |
| 3 | **云 Provider 端点未对照官方文档校正**：Meshy / Tripo / Rodin 的 endpoint 与字段是按下标写的 | 首次真实调用可能失败 | W1：拿到 Key 后逐一校正，端点集中在各 provider 文件顶部常量区 |
| 4 | **烘焙与 FBX 导出未在真实 Blender 上验证**：`recipes/bpy/*.py` 只做了静态检查 | 装了 Blender 的机器上可能报错 | M3：在带 Blender 的机器上跑一次，校正 Blender 4.x API 差异 |
| 5 | **前端未在真实 Electron 里跑过**：typecheck 与 vite build 通过，但 sidecar 拉起、视口加载 GLB、文件读取这些跨进程链路未实测 | 首次启动可能遇到路径/端口/权限问题 | M1：这是"骨架贯通"节点的验收内容 |
| 6 | **资产包批量（工作流 B）未实现**：Planner 与风格圣经只有配置模板 | 只能逐件生成 | Phase 2 |
